## [2026-09-23] — Исследование, архитектурный концепт и рабочий прототип

### 1. Исследования и анализ
* **Изучен репозиторий [torwin-job/musik](https://github.com/torwin-job/musik):**
  * Стек: Go (веб-сервер, стриминг, `modernc.org/sqlite`, векторный поиск в памяти) + Python (воркер, сканер тегов, CLAP-эмбеддинги).
  * Выявлена ключевая проблема: «холодный старт» — плеер бесполезен без готовой папки с MP3 или мощного GPU для многочасового сканирования.
* **Анализ открытых датасетов:**
  * Исследованы открытые базы: **Spotify 1.2M+ Songs** (Kaggle), **AcousticBrainz** (Essentia), **Free Music Archive** (FMA), **MTG-Jamendo**.
  * Сформулирован вывод: табличные 12D-фичи Spotify несовместимы напрямую с 512D CLAP-векторами, но идеальны как быстрый фильтр кандидатов на первом этапе (Stage 1).
* **Анализ роадмапа автора:**
  * Изучены планы создателя: мультиаккаунты («нормальные аккаунты»), разделение на долгий вкус и вечерний контекст, обучаемый сортировщик (Ranker) и адаптивный Discovery.
  * Достигнута полная совместимость: концепт Sidecar не ломает ни один из пунктов автора, а усиливает его модель новыми кандидатами.

### 2. Реальные бенчмарки и живые тесты
* Развернута связка: `InnerTube API` (поиск в YouTube Music) + `yt-dlp` (забор потока) + `Deno` (портативный JS-рантайм для обхода защиты `n-sig`).
* **Результаты боевого теста:**
  * Поиск трека: **1.2 сек**.
  * Скачивание чистого аудио (5.95 МБ, Opus 160 kbps): **0.8 сек** со скоростью **73.8 МБ/с**.
  * Реклама: 0%. Студийное качество звука.

### 5. Полноценный HTTP Sidecar API Server
* Развернут и запущен фоновый микросервис на Deno: `src/server.ts` (порт `:8795`).
* Эндпоинты:
  * `GET /health` — статус сервиса.
  * `GET /api/v1/tracks` — список и размеры кэшированных треков.
  * `GET /api/v1/fetch?q=...` и `POST /api/v1/fetch` — фоновое скачивание трека по HTTP.
* Успешно протестирована загрузка через HTTP API: скачан трек *The Beatles - Yesterday*.

### 6. Сборка Go Core и сквозная интеграция (End-to-End)
* **Обновление тулчейна Go:**
  * Установлен официальный компилятор Go 1.27.1 в `bin/go/` (исходники автора требовали `modernc.org/sqlite v1.55.0` с ограничением Go >= 1.25).
  * Выполнен `go mod tidy` и скомпилирован оригинальный исполняемый файл `bin/musik-player.exe` (18.7 МБ).
* **Инициализация БД:**
  * Из оригинального файла `src/musik/db/schema.py` извлечена и применена чистая схема SQLite в `data/db/musik.db`.
  * Запущен плеер `musik-player.exe` на `http://127.0.0.1:8787`.
* **Архитектурное открытие (Zero Tech Debt):**
  * В кодовой базе автора подтверждено: плеер умеет стримить треки со статусом `pending` напрямую из базы без необходимости предварительного расчета 512D CLAP-векторов (`stream.go` fallback to `s.Store.TrackPath`).
* **Модуль авто-регистрации (`musik-ingest`):**
  * Скомпилирован вспомогательный модуль `bin/musik-ingest.exe` на том же Go SQLite драйвере.
  * Сайдкар (`src/server.ts`) дополнен вызовом `musik-ingest.exe` и штатного `/api/reload`.
* **Боевой сквозной тест:**
  * Через HTTP API сайдкара (`POST :8795/api/v1/fetch`) запрошен трек `Pink Floyd - Comfortably Numb`.
  * Сайдкар за 7 секунд скачал трек, извлек метаданные, зарегистрировал запись в SQLite `tracks` и дернул `/api/reload`.
  * Плеер мгновенно добавил трек в каталог (`GET /api/library`).
  * Стриминг аудиопотока (`GET /api/stream/5`) отдает `HTTP 200 OK`, `Accept-Ranges: bytes`, 6.8 МБ.
