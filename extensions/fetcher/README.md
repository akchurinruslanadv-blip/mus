# musik-fetcher: Smart On-Demand Streaming, 12D Catalog Bridge & LRU Cache

`musik-fetcher` — это модульное расширение (Sidecar Add-on) для проекта [torwin-job/musik](https://github.com/torwin-job/musik), превращающее локальный музыкальный плеер в персональный стриминговый сервис с доступом к миллионным открытым каталогам музыки и динамической подкачкой треков.

---

## Ключевые возможности

1. **Динамическая подкачка треков на лету (Zero-Storage Startup):**
   * Вы можете загрузить каталог на 100 000+ треков без единого аудиофайла на сервере.
   * Плеер видит всю музыку, а аудиопоток скачивается автоматически только тогда, когда песня начинает играть.
2. **Внешний 12D-каталог Spotify & Радио-блендинг:**
   * Открытые базы данных (Spotify Audio Features, Kaggle 1.2M tracks) с 12 параметрами (`danceability`, `energy`, `valence`, `tempo`, etc.) используются для быстрого макро-поиска новинок.
   * Радио подмешивает подходящие находки из открытой базы к вашим любимым трекам.
3. **Холодный старт с 0 песен:**
   * Если у вас вообще нет своей музыки на сервере — система берет семена из внешнего каталога, запускает радио и учит ваш вкус с первого же клика.
4. **Умный 3 ГБ LRU-кеш с разделением Лайка ❤️ и кнопки 💾 «Сохранить навсегда»:**
   * **Лайк ❤️:** обучает нейросеть, добавляет в «Любимые песни», оставляет 512D-слепок и ссылку в базе навсегда, но аудиофайл может освободить место при переполнении 3 ГБ кеша (при повторном клике перекачивается за 1 сек).
   * **Кнопка 💾 «Сохранить навсегда»:** физически закрепляет аудиофайл на сервере с пожизненным иммунитетом от любого удаления.
5. **Каскадный поиск без задержек:**
   * Приоритет 1: Официальный релиз YouTube Music по студийному ID.
   * Приоритет 2: YouTube fallback для редких ремиксов и неофициальных записей.
   * Автопропуск (Skip on Fail): если трек недоступен, радио перешагивает через него без пауз и ошибок `404 file missing`.
6. **Zero-Intrusion (Гарантия чистой архитектуры):**
   * Ни единой правки в Go-коде оригинального плеера `musik`. Модуль подключается рядом и управляет базой и кешем через официальные API и события файловой системы.

## 4 Уровня хранения данных

| Уровень | Где лежит аудио | 512D след в БД | Поведение при переполнении 3 ГБ | Роль |
| :--- | :--- | :--- | :--- | :--- |
| **1. Внешний каталог 12D** | Нет аудио (0 КБ) | Нет (только 12D) | Не занимает место на диске | Справочник для поиска новинок и холодного старта |
| **2. Кеш dynamic/ (3 ГБ)** | В `dynamic/` | 512 float32 (2 КБ) | Вытесняется по LRU (самые старые) | Оперативный буфер прослушанного радио |
| **3. Лайк ❤️ (Любимая)** | В `dynamic/` | 512 float32 (2 КБ) | **Вытесняется по LRU!** (перекачивается за 1 сек) | Учит вкус, в плейлисте, экономит диск |
| **4. Сохранить навсегда 💾** | В `data/music/favorites/` | 512 float32 (2 КБ) | **Абсолютный иммунитет от удаления** | Ваша вечная офлайн-коллекция |

## Быстрый запуск

### Вариант 1: Запуск через Deno (Локально / VPS)

```bash
cd extensions/fetcher

# Запуск тестов
deno task test

# Запуск сервиса
deno task start
```

### Вариант 2: Запуск в Docker Compose

Добавьте сервис `fetcher` в ваш `docker-compose.yml` (или используйте готовый `docker-compose.addon.yml`):

```yaml
services:
  fetcher:
    build: ./extensions/fetcher
    ports:
      - "8795:8795"
    environment:
      - FETCHER_PORT=8795
      - CACHE_MAX_GB=3.0
      - MUSIK_PLAYER_URL=http://player:8787
    volumes:
      - ./data:/app/data
      - ./dynamic:/app/dynamic
    depends_on:
      - player
```

## HTTP API Спецификация

| Метод | Путь | Описание |
| :--- | :--- | :--- |
| `GET` | `/health` | Проверка здоровья сервиса |
| `GET` | `/api/v1/cache` | Статистика 3 ГБ кеша (объем, процент использования, закрепленные) |
| `POST` | `/api/v1/cache/clean` | Ручной вызов LRU-очистки до 85% лимита |
| `POST` | `/api/v1/fetch` | Скачивание трека по названию или ссылке (`{ query, mode: "cache"\|"pin" }`) |
| `GET` | `/api/v1/tracks/:id/resolve` | Разрешение аудиопотока перед воспроизведением (предотвращает 404) |
| `POST` | `/api/v1/tracks/:id/pin` | **💾 Сохранить навсегда:** перенос аудио в `favorites/` с вечным иммунитетом |
| `DELETE`| `/api/v1/tracks/:id/pin` | Снятие вечного закрепления (файл возвращается под управление LRU) |
| `GET` | `/api/v1/catalog/seeds` | Получение разнообразных семян для холодного старта при 0 треков в базе |
| `POST` | `/api/v1/catalog/blend` | Поиск кандидатов в 12D внешнем каталоге по акустическому вектору |

## Импорт датасетов и списков

В модуль включена утилита `scripts/import_dataset.ts`:

```bash
# Импорт обычного текстового списка (Артист — Название)
deno task import --file="vk_music_2001_tracks.txt" --format=text --limit=500

# Импорт CSV-датасета Spotify с 12 параметрами
deno task import --file="spotify_12d_features.csv" --format=csv --limit=50000
```
